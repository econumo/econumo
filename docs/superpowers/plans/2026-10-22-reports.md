# Reports v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/reports` page with tabs holding three look-back reports (Spending, Cash flow, Net worth) over a budget or the user's own accounts, fed by two new server read endpoints.

**Architecture:** The budget feature hosts the report computation because it already owns the monthly SQL, the budget rules and the currency conversion: budget scope reuses `BuildBudgetPlan` unchanged (so numbers equal Plan by construction) and converts each row to the budget currency; "my accounts" scope uses one new grouped-by-month query. Two `GET` routes under `/api/v1/report/`, registered from `internal/budget/api`. The SPA fetches, then rolls up / stacks / compares / projects in pure functions and draws with recharts; tabs live in a persisted zustand store.

**Tech Stack:** Go (stdlib http, hand-built SQL for sqlite + pgsql), React 19 + TanStack Query + zustand + recharts 3 + react-i18next, vitest.

**Spec:** `docs/superpowers/specs/2026-10-22-reports-design.md`

## Global Constraints

- Routes: `GET /api/v1/report/get-flow-report`, `GET /api/v1/report/get-net-worth-report`; standard envelope; swag annotation block on each handler; `make swagger` regenerates committed docs.
- Features never import features (archtest). New cross-feature needs go through a port in `internal/budget/ports.go` + an adapter in `internal/server`.
- Budget-scope figures must equal `get-budget-plan`'s for the same budget, rows and months (parity test in Task 3).
- Budget scope shows months BEFORE the budget start; months after an ended budget's end month are not shown.
- Window: at most 240 months; larger → 400 field error on `to`, code `common.invalid_choice`.
- SQL: every new query has a sqlite and a pgsql form; `.sql`/SQL strings ASCII-only; aggregate by month in SQL.
- Every new user-facing action fires a `METRICS` event (`web/src/lib/metrics.ts`, `app`-prefixed camelCase) at its success point; `metrics-coverage.test.ts` must pass.
- Every new UI string is a key in all 11 `locales/<lang>.json` (en reference; real translations, `{var}` placeholders identical); `pluralPick` pipe-joined values for plurals.
- No bold for visual hierarchy; consistent colour per row across charts; readable in light and dark theme.
- Phone first: phone layout is the primary layout, desktop enhances (tab strip, Sankey).
- Tabs are stored per user on the device only; Reports opens on the FIRST tab.
- `docs/regression-test-plan.md` gets a Reports section (📱 markers where phone-specific).
- Comments sparingly (CLAUDE.md rule). `gofmt`, `go vet`, oxlint clean.

## Review Focus

1. **A user with no transactions at all** (or a budget with no member transactions): endpoints return `months: [currentMonth]` with empty rows; every report renders an empty state, never a crash or NaN. → tests in Task 2 (`TestFlowReport_NoTransactions`) and Task 7 (`ReportsPage.empty.test.tsx`).
2. **Rows in a currency other than the report currency** (foreign-currency account, or a budget element with its own currency): amounts are converted per month; totals still equal Plan when element currency == budget currency. → `TestFlowReport_Budget_ElementCurrencyConverted` (Task 3), `TestFlowReport_Personal_ForeignAccountConverted` (Task 2).
3. **A stored tab whose budget/row/account no longer exists** (deleted budget, lost access → 400/404 from the API): the tab falls back to "My accounts" scope and keeps working. → `reportTabs.test.ts` "repairs a tab whose budget is gone" (Task 7).
4. **Current, unfinished year/quarter** in Over time: drawn as projected with a dashed outline and labelled; Compare years cuts both years to the same months. → `reportMath.test.ts` cases (Task 6).
5. **Deleted accounts** (zeroed by a correction): they keep their history in Spending/Cash flow and drop to 0 in Net worth after deletion; they don't appear as phantom groups with zero everywhere. → `TestNetWorthReport_DeletedAccountZeroAfterDeletion` (Task 4), net worth table hides all-zero accounts (Task 10).
